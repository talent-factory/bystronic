== Zusammenfassung

Dieses Tutorial führt Sie in `pytest` ein, das führende Test-Framework für Python. Sie lernen die Grundlagen des Testens, pytest-spezifische Features wie Test-Vorrichtungen (Fixtures), Parametrisierung und Mocking kennen. Das Tutorial enthält praktische Beispiele und Übungen zur Vertiefung des Gelernten.

== Einführung

=== Was ist pytest?

pytest ist ein ausgereiftes, vollständiges Test-Framework für Python, das es ermöglicht, einfache Unit-Tests bis hin zu komplexen funktionalen Tests zu schreiben. Es zeichnet sich durch seine einfache Syntax und mächtigen Features aus.

**Warum pytest verwenden?**

* Einfache und intuitive Syntax
* Automatische Test-Erkennung
* Detaillierte Fehlermeldungen
* Umfangreiche Plugin-Unterstützung
* Test-Vorrichtungen (Fixtures) für Setup/Teardown
* Parametrisierte Tests
* Parallele Testausführung

[IMPORTANT]
====
pytest ist nicht nur ein Test-Framework, sondern ein komplettes Ökosystem für Qualitätssicherung in Python-Projekten.
====

== Grundlagen des Testens

=== Ihr erster Test

Erstellen wir eine einfache Funktion und den dazugehörigen Test:

**src/calculator.py**
[source,python]
----
def add(a: int, b: int) -> int:
    """Addiert zwei Zahlen."""
    return a + b

def subtract(a: int, b: int) -> int:
    """Subtrahiert b von a."""
    return a - b

def multiply(a: int, b: int) -> int:
    """Multipliziert zwei Zahlen."""
    return a * b

def divide(a: float, b: float) -> float:
    """Dividiert a durch b."""
    if b == 0:
        raise ValueError("Division durch Null ist nicht erlaubt")
    return a / b
----

**tests/test_calculator.py**
[source,python]
----
import pytest
from src.calculator import add, subtract, multiply, divide

def test_add():
    """Test für die Addition."""
    assert add(2, 3) == 5
    assert add(-1, 1) == 0
    assert add(0, 0) == 0

def test_subtract():
    """Test für die Subtraktion."""
    assert subtract(5, 3) == 2
    assert subtract(0, 5) == -5
    assert subtract(-2, -3) == 1

def test_multiply():
    """Test für die Multiplikation."""
    assert multiply(3, 4) == 12
    assert multiply(-2, 3) == -6
    assert multiply(0, 100) == 0

def test_divide():
    """Test für die Division."""
    assert divide(10, 2) == 5.0
    assert divide(7, 2) == 3.5

def test_divide_by_zero():
    """Test für Division durch Null."""
    with pytest.raises(ValueError, match="Division durch Null"):
        divide(10, 0)
----

== Test-Vorrichtungen (Fixtures)

Test-Vorrichtungen sind eine der mächtigsten Features von pytest. Sie ermöglichen es, Setup- und Teardown-Code zu definieren, der vor und nach Tests ausgeführt wird.

=== Grundlegende Fixtures

[source,python]
----
import pytest
from src.calculator import Calculator

@pytest.fixture
def calculator():
    """Test-Vorrichtung: Erstellt eine Calculator-Instanz."""
    return Calculator()

@pytest.fixture
def sample_data():
    """Test-Vorrichtung: Stellt Beispieldaten bereit."""
    return {
        'numbers': [1, 2, 3, 4, 5],
        'operations': ['+', '-', '*', '/'],
        'results': [15, -5, 120, 0.2]
    }

def test_calculator_with_fixture(calculator):
    """Test mit Calculator-Fixture."""
    result = calculator.add(2, 3)
    assert result == 5

def test_with_sample_data(sample_data):
    """Test mit Beispieldaten."""
    numbers = sample_data['numbers']
    assert len(numbers) == 5
    assert sum(numbers) == 15
----

=== Mocking

Mocking ist essentiell für das Testen von Code, der externe Abhängigkeiten hat:

[source,python]
----
import pytest
from unittest.mock import Mock, patch
from src.weather_service import WeatherService

def test_weather_service_with_mock():
    """Test mit Mock-Objekt."""
    # Mock erstellen
    mock_api = Mock()
    mock_api.get_temperature.return_value = 25.0

    # Service mit Mock initialisieren
    weather_service = WeatherService(api_client=mock_api)

    # Test ausführen
    temp = weather_service.get_current_temperature("Berlin")

    # Assertions
    assert temp == 25.0
    mock_api.get_temperature.assert_called_once_with("Berlin")

@patch('src.weather_service.requests.get')
def test_weather_api_call(mock_get):
    """Test mit patch decorator."""
    # Mock Response konfigurieren
    mock_response = Mock()
    mock_response.json.return_value = {'temperature': 22.5}
    mock_response.status_code = 200
    mock_get.return_value = mock_response

    # Test ausführen
    service = WeatherService()
    temp = service.fetch_temperature("München")

    # Assertions
    assert temp == 22.5
    mock_get.assert_called_once()
----

== Test-Driven Development (TDD)

TDD ist eine Entwicklungsmethodik, bei der Tests vor dem eigentlichen Code geschrieben werden:

=== TDD-Zyklus

1. **Red**: Test schreiben, der fehlschlägt
2. **Green**: Minimalen Code schreiben, damit Test besteht
3. **Refactor**: Code verbessern, ohne Funktionalität zu ändern

=== Praktisches TDD-Beispiel

**Schritt 1: Test schreiben (Red)**
[source,python]
----
# tests/test_string_utils.py
import pytest
from src.string_utils import reverse_string, is_palindrome

def test_reverse_string():
    """Test für String-Umkehrung."""
    assert reverse_string("hello") == "olleh"
    assert reverse_string("") == ""
    assert reverse_string("a") == "a"

def test_is_palindrome():
    """Test für Palindrom-Erkennung."""
    assert is_palindrome("racecar") == True
    assert is_palindrome("hello") == False
    assert is_palindrome("") == True
    assert is_palindrome("A man a plan a canal Panama") == True
----

**Schritt 2: Minimale Implementierung (Green)**
[source,python]
----
# src/string_utils.py
def reverse_string(s: str) -> str:
    """Kehrt einen String um."""
    return s[::-1]

def is_palindrome(s: str) -> bool:
    """Prüft, ob ein String ein Palindrom ist."""
    # Normalisierung: Kleinbuchstaben, keine Leerzeichen
    normalized = ''.join(s.lower().split())
    return normalized == normalized[::-1]
----

**Schritt 3: Refactoring**
[source,python]
----
# src/string_utils.py (verbesserte Version)
import re

def reverse_string(s: str) -> str:
    """Kehrt einen String um.

    Args:
        s: Der umzukehrende String

    Returns:
        Der umgekehrte String
    """
    if not isinstance(s, str):
        raise TypeError("Input muss ein String sein")
    return s[::-1]

def is_palindrome(s: str) -> bool:
    """Prüft, ob ein String ein Palindrom ist.

    Args:
        s: Der zu prüfende String

    Returns:
        True wenn Palindrom, False sonst
    """
    if not isinstance(s, str):
        raise TypeError("Input muss ein String sein")

    # Nur Buchstaben und Zahlen behalten, Kleinschreibung
    normalized = re.sub(r'[^a-zA-Z0-9]', '', s).lower()
    return normalized == normalized[::-1]
----

=== Test-Organisation

class TestCalculator:
    """Testklasse für Calculator-Funktionalität."""

    def setup_method(self):

        self.calculator = Calculator()

        """Test grundlegender Operationen."""

        """Test von Grenzfällen."""

    def test_error_conditions(self):
        """Test von Fehlerbedingungen."""

    def __init__(self, initial_balance: float = 0.0):
        if initial_balance < 0:
            raise ValueError("Anfangssaldo kann nicht negativ sein")
        self._balance = initial_balance
        self._transactions = []
        if initial_balance > 0:
            self._transactions.append(f"Konto eröffnet mit {initial_balance}€")

    def deposit(self, amount: float) -> None:
        if amount <= 0:
            raise ValueError("Einzahlungsbetrag muss positiv sein")
        self._balance += amount
        self._transactions.append(f"Einzahlung: +{amount}€")

    def withdraw(self, amount: float) -> None:
        if amount <= 0:
            raise ValueError("Abhebungsbetrag muss positiv sein")
        if amount > self._balance:
            raise ValueError("Unzureichendes Guthaben")
        self._balance -= amount
        self._transactions.append(f"Abhebung: -{amount}€")

    def get_balance(self) -> float:
        return self._balance

    def get_transaction_history(self) -> list:
        return self._transactions.copy()
